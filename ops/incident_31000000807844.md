# Incident 31000000807844 — MCP 도구 범위 제한 미흡

- **출처:** 보안팀 취약점 리포트
- **심각도:** 긴급
- **상태:** 분석 완료 / 수정 미착수
- **작성일:** 2026-11-18

## 보안팀 권고

원격 MCP 서버 구성에서 `tools=["*"]`와 같은 전체 허용 설정을 제거하고, Storage 도구(`listBlobs`, `readBlobContent` 등)가 호출자의 세션 prefix(`sessions/<id>/`) 범위를 반드시 검증하도록 수정.

## 원인 분석

### 1. 전체 허용 설정
- `app/src/runtime/mcp_config.py:42`: `tools=["*"]` — 원격 서버가 노출하는 모든 도구가 세션에 등록됨.
- `app/tests/test_mcp_config.py:37`이 해당 값을 기대하고 있음.
- 적용 위치: `state.py:204`, `state.py:453`, `jobs.py:61`, `teams/orchestrator.py:115` (모든 세션 공통).

### 2. 세션 prefix 검증 누락
- `app/src/runtime/isolation.py`에 `build_blob_prefix` / `is_blob_name_in_isolation`(`sessions/<id>/`)이 존재하나, 업로드 blob 이름 생성(`storage/file_validation.py:101`)과 첨부 검증(`api/sse_utils.py:68`)에서만 사용됨.
- 원격 MCP Storage 도구 호출 경로에는 검증이 없음.
- `runtime/mcp_client.py`, `mcp_config.py`가 헤더/세션 식별자를 MCP 서버에 전달하지 않아 서버가 호출자를 구분할 수 없음.
- `normalize_isolation_session_id`는 입력이 없으면 thread_id를 fallback으로 사용 — 인증된 사용자 ID와 연결된 값인지 확인 필요.

### 3. 허용 목록 우회 경로
- `COPILOT_API_ALLOWED_TOOLS` 설정 시 `runtime/tool_policy.py`의 `apply_tool_policy`가 `_get_remote_mcp_tool_names()`로 원격 서버의 **모든** 도구 이름을 `available_tools`에 추가 → `mcp_config`에서 화이트리스트를 적용해도 전체 허용으로 되돌려짐.
- `GET /v1/mcp/tools`(`api/routes.py:694`)도 필터 없이 전체 목록 반환.

## 영향

- 프롬프트(또는 업로드 문서의 인젝션)로 LLM이 `listBlobs`/`readBlobContent`를 임의 prefix·blob 이름으로 호출 → **타 세션 업로드 파일 열람(세션 간 데이터 유출, IDOR/BOLA 유형)**.
- 서버 쪽 `startswith` 단순 검사는 `..`, `%2e%2e`, `sessions//` 등으로 우회 가능.
- 원격 서버 침해가 아니라, 앱이 약속한 세션 격리를 실제 데이터 접근 경로에서 강제하지 않는 문제.

## 수정 계획

1. **도구 화이트리스트:** `tools=["*"]` 제거, 필요한 도구명 명시 목록(env 설정, 기본값 빈 목록 = deny by default). SDK 내장 도구는 `MCPServerConfig.tools` 범위가 아니므로 포함하지 않음(`tool_policy.py`의 `excluded_tools`/`available_tools`가 별도 제어). 서버별 `tools` 필터의 적용 범위는 설치된 SDK 코드로 구현 시 확인.
2. **허용 목록 공유:** `tool_policy._get_remote_mcp_tool_names()` 결과와 `GET /v1/mcp/tools`를 동일 허용 목록과 교집합 처리.
3. **세션 ID 전달:** `build_mcp_servers_config(isolation_session_id)`로 세션별 `headers`에 인증된 세션 식별자 전달 (서명/신뢰 가능한 값).
4. **서버 측 prefix 강제 (원격 MCP 서버, 핵심):** 인증된 컨텍스트의 세션 ID 기준으로, 경로 정규화 후 `sessions/<id>/` 범위만 허용. `listBlobs`는 prefix를 서버가 덮어씀. 모델이 넘긴 인자는 신뢰하지 않음.
5. **클라이언트 방어선:** tool-call 인자를 `is_blob_name_in_isolation`으로 검사하는 훅 추가(보조 수단).
6. **테스트:** `test_mcp_config.py` 갱신, 타 세션 prefix / path traversal 거부 테스트 추가.

## 미확인 사항 / 후속 확인

- 원격 MCP 서버 코드 위치 및 기존 prefix 검증 여부 (이 레포에 구현 없음).
- `isolation_session_id`의 출처가 인증된 사용자와 바인딩되는지.
- 서버가 이 앱 외 경로로도 호출 가능한지 (서명/mTLS 필요 여부).
